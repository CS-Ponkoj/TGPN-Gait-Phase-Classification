The question

Recognizing a state starts with defining the reference.

Walking unfolds over time. A single silhouette captures a pose; a sequence also captures how that pose changes. This project investigates both views using CASIA C thermal silhouette sequences from normal, slow, fast, and bag-carrying walking conditions.

The reference labels are generated from silhouette-spread intervals. That makes their provenance central to the research: evaluating agreement with operational labels and establishing physical gait phases are different scientific questions.

The representation

Four operational states in a repeating sequence.

The implementation uses four states, P0–P3. Their vocabulary expresses the intended gait interpretation and provides a consistent interface for annotation, training, and evaluation.

P0Initial contact / loading
P1Mid-stance
P2Terminal stance / pre-swing
P3Swing

The reference matters. The current deterministic labels are provisional. These state names do not independently establish anatomical phase or continuity of the same reference foot. Physical gait-phase validation requires independent annotation and expert adjudication.

The method

Spatial appearance meets temporal context.

Thermal GaitPhaseNet (TGPN) processes short clips of aligned, single-channel silhouettes. It combines body appearance and adjacent-frame differences, models their evolution over time, and produces a state prediction and a boundary prediction for each frame.

An EfficientNet-B0 encoder supplies appearance features. A separate motion branch reads absolute differences between adjacent frames. Residual dilated temporal convolutions and self-attention combine the resulting representations. Training includes state and boundary losses with temporal regularization.

Clip-based inference. TGPN uses both earlier and later frames within a clip and averages probabilities across overlapping windows. Causal control, measured real-time performance, and clinical deployment require separate evaluation.

How we investigate

Compare the inputs, protect the evaluation.

The evaluation brings together subject-independent partitions, visual baselines, temporal controls, and supervision diagnostics. The aim is to examine what each comparison supports while keeping target provenance visible.

Evaluation considers subject-level macro F1, per-class behavior, boundary timing, and subject-bootstrap uncertainty. The cycle-position diagnostic is kept separate from visual comparisons because its inputs are related to how the reference is constructed.

Separate subjects

Development folds and held-out subjects keep model selection separate from final evaluation.

Lock training choices

Development launchers exclude the test partition. Final neural evaluation requires explicit acknowledgement and a fixed training duration.

Preserve the evidence

Configurations, predictions, metrics, and environment records make each run traceable and support analysis from saved outputs.

The implemented codebase

From source data to reproducible analysis.

The Python package connects data preparation, annotation checks, subject partitioning, model training, and evaluation. It also generates summary assets from saved predictions so analysis remains connected to recorded experiments.

Data preparation and annotation

Manifest construction records provenance and image checksums. Preparation validates copied images and fold manifests before marking a training tree ready. Annotation utilities support provisional labels, independent-review workflows, and consistency audits.

CASIA data must be obtained under its source terms. Images and prepared image copies are not bundled with the repository.

Models, training, and run records

Model implementations include classical, single-frame, and temporal approaches. Training launchers provide development-fold workflows and explicit safeguards for final evaluation. Each run records its settings, environment, predictions, and metrics, with checkpoints and learning curves where applicable.

Generated weights and experiment outputs remain local. A code clone does not contain the complete experimental evidence.

Get started with the code

Use Python 3.11. From the repository root in PowerShell:

python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m gait_phase.cli --help

Follow the reproduction guide for licensed-data preparation, GPU setup, training, and evidence generation.

Implementation validation

The test suite covers configuration, manifests, annotations, subject splitting, prepared data, model contracts, metrics, experiment summaries, and the command-line workflow.

.\.venv\Scripts\python.exe -m pytest tests -q

These checks validate implementation behavior. They do not reproduce all training experiments or establish anatomical label validity.

Research scope

Keep the question and the evidence aligned.

The current study focuses on thermal silhouettes and operational state modeling. Independent physical-phase validation, clinical use, and generalization to other acquisition settings require additional evidence.

The repository also preserves earlier CASIA A materials and single-frame ResNet152V2/InceptionV3 experiments. They document the research history and are separate from the revised four-state CASIA C study. OU-ISIR is excluded from this study.

This overview describes the research design and implementation. Detailed experimental findings belong in the accompanying paper.
